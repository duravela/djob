# Reporting security issues

djob is a preview project. There is no stable release series or promised support
window yet. Assess the exact source revision and toolchain before deployment;
older release candidates may lack later security or correctness fixes.

Do not report vulnerabilities, credentials or private deployment details in
public issues. If GitHub displays **Report a vulnerability** for the repository,
use that private reporting channel. Otherwise contact the repository owner
through a private channel shown on their GitHub profile, or request a private
contact channel without disclosing vulnerability details. A reporting email and
response-time commitment will be added when the project owner establishes them.

Include the affected revision/version, impact, prerequisites and a minimal
reproduction with synthetic data. Do not test against systems you do not own
or have permission to assess. The project makes no claim that a vulnerability
scan or simulator run proves absence of security defects.
